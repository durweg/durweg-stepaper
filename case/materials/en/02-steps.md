# Workflow steps: stepaper

Workflow name: `stepaper` (start it with `durweg start stepaper <name-of-this-run>`). Title: read a paper and check my understanding with slides. 8 steps, in order; steps marked ✅ go on only after the user confirms.

| # | Step | What it does | What it delivers | User decides |
|---|---|---|---|---|
| 1 | Choose the language (`language`) | Ask the user which language this run uses (for example Chinese, English, German). All notes, the metrics guide, the slides and speaker notes are written in it, and the agent talks to the user in it. | The language of this run. | ✅ |
| 2 | Find the core claim (`core-claim`) | Read the abstract and write in one or two sentences the concrete problem the paper solves and its core claim. | Core-claim note: which concrete problem, what the paper claims. | ✅ |
| 3 | Read step by step, question every step (`walkthrough`) | Go through cause → method → why it works → how it was tested → results together with the user, one step at a time (one part of the method at a time); after each, ask whether the user understood and invite their own view or rebuttal, and answer their questions; if they did not understand, explain more simply, without adding formulas, figures or long explanations. Record per step the key points, the user's questions and answers, their retelling and views; views that need the results are marked "to be checked" and checked in the results step. Finally note what the questions changed in the understanding of the core claim. | Step-by-step discussion notes: key points, the user's questions and answers, retellings and views, and what the questions changed. | ✅ |
| 4 | Metrics guide (`metrics`) | List every evaluation metric in the paper; for each, only two things: what it is for, and how to read it (higher or lower is better, range, how to read the paper's numbers). No derivations; short enough for the user to retell. | Metrics guide (markdown): one short paragraph per metric. | ✅ |
| 5 | Retell and judge (`retell-judge`) | First ask the user to retell the core claim in their own words as a comparison (is A or B better?), then to judge: did the paper solve its problem, how strong is the evidence, what are the reservations, did they reach their own goal (understanding the paper). Write it up in the user's words; mark Claude's additions or rebuttals separately, and the user decides whether to keep them. | The user's one-sentence retelling (A vs B) + judgement and reservations. | ✅ |
| 6 | Outline the slides (`outline`) | Each slide answers one question, and its title is that slide's one-sentence conclusion; default order: core claim, cause, method, why it works, how it was tested, results (A vs B, with metrics and numbers), questions and judgement, retelling and open questions. | Slide outline: each slide's title conclusion and the figure or numbers on it. | ✅ |
| 7 | Make the slides (`slides`) | Build the deck from the confirmed outline: key figures from the paper, little text per slide, no piles of formulas; the results slide names the metric, the comparison and the source; speaker notes on every slide. | The slide deck (PPT file). | |
| 8 | Rehearse and check (`rehearse`) | Rehearse slide by slide: does each slide answer its question, do the slides form one line, do the numbers match the paper; note what to change and change it; ask the user to open the file in PowerPoint and check how it looks. | The corrected deck + the list of problems found and fixed. | ✅ |
